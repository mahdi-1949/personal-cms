# Core CMS — هسته‌ی مدیریت سایت اختصاصی

نسخه‌ی `0.1.0` یک شروع قابل اجرا برای CMS شرکتی و خدماتی است. نام Core CMS موقت است. ظاهر هر سایت می‌تواند مستقل از پنل و هسته ساخته شود. این نسخه هنوز محصول آماده‌ی تحویل به مشتری نیست.

مخزن اصلی توسعه: [mahdi-1949/personal-cms](https://github.com/mahdi-1949/personal-cms). توسعه عمومی در گیت‌هاب انجام می‌شود؛ استقرار روی هاست واقعی پس از تکمیل و بررسی نسخه اول خواهد بود. داده و تنظیمات هر مشتری مستقل از مخزن کد نگهداری می‌شوند.

## اجرا روی کامپیوتر

Node.js نسخه‌ی 24.15 یا جدیدتر از شاخه‌ی 24 لازم است. این نسخه از SQLite داخلی Node استفاده می‌کند و به نصب بسته‌های npm وابسته نیست. `node:sqlite` در این شاخه release candidate است؛ پیش از استفاده‌ی عملیاتی نسخه‌ی runtime باید تثبیت و ارزیابی شود.

```bash
git clone https://github.com/mahdi-1949/personal-cms.git
cd personal-cms
npm run create-admin
npm start
```

ایمیل و رمز مدیر به‌صورت تعاملی پرسیده می‌شود. رمز در ترمینال نمایش داده نمی‌شود؛ حداقل ۱۲ کاراکتر وارد کنید. حساب و رمز پیش‌فرض وجود ندارد.

پنل: `http://localhost:3000/admin` — سایت: `http://localhost:3000`

برای توسعه: `npm run dev` — برای تست: `npm test`

دیتابیس با اولین اجرا در `data/cms.sqlite` ساخته می‌شود. اجرای سرور فقط روی loopback است. سرور، تنظیمات را از متغیرهای محیطی می‌خواند؛ فایل `.env.example` فقط نمونه است و خودکار بارگذاری نمی‌شود.

## امکانات فعلی

- پنل فارسی و راست‌به‌چپ، نمایش آمار و جست‌وجو در عنوان.
- ورود مدیر با هش scrypt، نشست ۸ ساعته، کوکی HttpOnly، محدودیت تلاش ورود، بررسی Origin و CSRF.
- ایجاد، ویرایش و حذف محتوا؛ دو وضعیت پیش‌نویس و منتشرشده؛ کنترل تعارض ویرایش.
- صفحات و ماژول‌های خدمات، مقالات و نمونه‌کار؛ فعال‌سازی ماژول توسط مدیر بدون پاک‌کردن داده.
- نقش editor در مدل و API پشتیبانی می‌شود؛ رابط ساخت و مدیریت کاربران هنوز وجود ندارد.
- عنوان و توضیحات متا، canonical، Open Graph، sitemap و robots.
- رندر HTML سمت سرور و خروجی ثابت عمومی شامل محتوای منتشرشده از ماژول‌های فعال.

متن محتوا فعلاً ساده است؛ HTML ارسالی اجرا نمی‌شود. برای صفحه‌ی اصلی یک صفحه با آدرس `home` بسازید و منتشر کنید. سایر آدرس‌ها فعلاً انگلیسی هستند. لینک‌ها با اسلش پایانی یکسان‌سازی می‌شوند.

## خروجی برای GitHub Pages

پنل و دیتابیس روی Pages اجرا نمی‌شوند. Pages تنها خروجی ثابت عمومی را میزبانی می‌کند؛ پنل و API نیازمند سرویس بک‌اند هستند.

بعد از ساخت و انتشار محتوا، در Bash/macOS/Linux:

```bash
CMS_PUBLIC_URL=https://YOUR-ACCOUNT.github.io/YOUR-REPOSITORY npm run export
```

در PowerShell ویندوز:

```powershell
$env:CMS_PUBLIC_URL = 'https://YOUR-ACCOUNT.github.io/YOUR-REPOSITORY'
npm run export
```

خروجی در `dist/` است. این پوشه شامل پنل، دیتابیس، اطلاعات کاربران و پیش‌نویس‌ها نیست. مسیر دارایی‌ها و canonical متناسب با زیرمسیر Pages ساخته می‌شود. فقط همین خروجی باید روی Pages منتشر شود. خروجی Pages قابلیت اختیاری است؛ برنامه فعلی، استقرار CMS روی هاست واقعی پس از تکمیل نسخه اول است. وب‌هوک و انتشار خودکار بعداً اضافه می‌شود.

## مسیرهای پایه

| مسیر | کاربرد |
| --- | --- |
| `/admin` | پنل مدیر |
| `/api/auth/login`, `/api/auth/me`, `/api/auth/logout` | ورود و نشست |
| `/api/content` | فهرست و ساخت محتوا، نیازمند نشست |
| `/api/content/:id` | ویرایش یا حذف؛ نیازمند CSRF و نسخه‌ی فعلی |
| `/api/settings` | تنظیمات سایت؛ تغییر فقط توسط مدیر |
| `/api/modules` | تعریف ماژول‌ها |
| `/api/public/content` | محتوای منتشرشده، بدون ورود |

برای نوشتن در API، Origin باید با `CMS_ORIGIN` برابر باشد و هدر `X-CSRF-Token` از نشست فعلی گرفته شود. PUT و DELETE محتوا به `expected_updated_at` نیاز دارند. API عمومی در حال حاضر CORS بین دامنه‌ها ندارد؛ اتصال مستقیم یک frontend در دامنه‌ی دیگر باید جداگانه طراحی شود.

## قبل از تحویل به مشتری

مدیریت رسانه، نقش‌ها و مدیریت کاربران، بازیابی رمز، بکاپ و بازیابی آزموده‌شده، گزارش رخدادها، ریدایرکت پس از تغییر آدرس، دسته‌بندی، بلوک‌های محتوای قابل ویرایش، فرم تماس، تست مرورگر، ارزیابی امنیت و استقرار staging هنوز باقی است. `NODE_ENV=production` بدون HTTPS و کوکی Secure اجرا را رد می‌کند؛ این کنترل جای بررسی امنیت و راه‌اندازی صحیح پراکسی را نمی‌گیرد.

اطلاعات واقعی مشتری، کلیدها، رمزها و بکاپ‌ها وارد مخزن عمومی نمی‌شوند. برای هر مشتری دیتابیس و تنظیمات مستقل در نظر گرفته شده است. مجوز بازاستفاده از کد هنوز انتخاب نشده است؛ عمومی‌بودن مخزن به معنی وجود LICENSE نیست.
