# Core CMS — هسته‌ی مدیریت سایت اختصاصی

نسخه‌ی `0.5.0` یک CMS در حال توسعه برای سایت‌های شرکتی و خدماتی است. نام Core CMS موقت است. ظاهر هر سایت می‌تواند مستقل از پنل و هسته ساخته شود. این نسخه هنوز محصول آماده‌ی تحویل به مشتری نیست.

مخزن اصلی توسعه: [mahdi-1949/personal-cms](https://github.com/mahdi-1949/personal-cms). توسعه عمومی در گیت‌هاب انجام می‌شود؛ استقرار روی هاست واقعی پس از تکمیل و بررسی نسخه اول خواهد بود. داده و تنظیمات هر مشتری مستقل از مخزن کد نگهداری می‌شوند.

## اجرا روی کامپیوتر

Node.js نسخه‌ی 24.15 یا جدیدتر از شاخه‌ی 24 لازم است. این نسخه از SQLite داخلی Node استفاده می‌کند ؛ Nodemailer برای SMTP و Sharp برای پردازش تصاویر استفاده می‌شوند. پیش از استفاده‌ی عملیاتی نسخه runtime و سیستم‌عامل باید تثبیت و ارزیابی شوند.

```bash
git clone https://github.com/mahdi-1949/personal-cms.git
cd personal-cms
npm ci --ignore-scripts
npm run create-admin
npm start
```

ایمیل و رمز مدیر به‌صورت تعاملی پرسیده می‌شود. رمز در ترمینال نمایش داده نمی‌شود؛ حداقل ۱۲ کاراکتر وارد کنید. حساب و رمز پیش‌فرض وجود ندارد.

پنل: `http://localhost:3000/admin` — سایت: `http://localhost:3000`

برای توسعه: `npm run dev` — برای بررسی ساختار کد: `npm run check` — برای تست: `npm test`

دیتابیس با اولین اجرا در `data/cms.sqlite` ساخته می‌شود. اجرای سرور فقط روی loopback است. سرور، تنظیمات را از متغیرهای محیطی می‌خواند؛ فایل `.env.example` فقط نمونه است و خودکار بارگذاری نمی‌شود.

## امکانات فعلی

- پنل فارسی و راست‌به‌چپ، نمایش آمار و جست‌وجو در عنوان.
- ورود مدیر با هش scrypt، نشست ۸ ساعته، کوکی HttpOnly، محدودیت تلاش ورود، بررسی Origin و CSRF.
- ایجاد، ویرایش و حذف محتوا؛ دو وضعیت پیش‌نویس و منتشرشده؛ کنترل تعارض ویرایش.
- صفحات و ماژول‌های خدمات، مقالات و نمونه‌کار؛ فعال‌سازی ماژول توسط مدیر بدون پاک‌کردن داده.
- مدیریت کاربران در پنل: ساخت، تغییر نقش، فعال/غیرفعال‌کردن و تعیین رمز؛ آخرین مدیر فعال قابل غیرفعال‌کردن نیست.
- تغییر رمز توسط صاحب حساب، مشاهده و بستن نشست‌های خود؛ تغییر حساب تمام نشست‌های قبلی او را باطل می‌کند.
- مدیریت تصاویر PNG/JPEG با محدودیت ۵ مگابایت و ۱۶ میلیون پیکسل، alt و جلوگیری از حذف تصاویر استفاده‌شده.
- ویرایشگر بلوکی: عنوان، متن، تصویر و دکمه به یک صفحه؛ ترتیب و حذف بلوک‌ها.
- مدیریت منوی سایت با اتصال به شناسه محتوا؛ لینک صفحات پیش‌نویس و ماژول غیرفعال در خروجی عمومی پنهان می‌شود.
- دسته‌بندی چندگانه مقالات، آرشیو عمومی دسته‌ها و حفظ لینک پس از تغییر آدرس دسته.
- ریدایرکت خودکار آدرس قبلی محتوای منتشرشده و مدیریت ریدایرکت دستی به مقصد داخلی؛ مقصد خصوصی انتقال عمومی ندارد.
- فرم تماس اختیاری، توکن یک‌بارمصرف، honeypot و محدودیت ارسال؛ صندوق پیام صفحه‌بندی‌شده فقط برای مدیر.
- بکاپ کامل دیتابیس و تصاویر، بررسی SHA-256/سلامت SQLite و بازیابی در مسیر تازه با ابطال نشست‌ها.
- migration تراکنشی و افزایشی از دیتابیس نسخه‌های 0.1 و 0.2 بدون حذف محتوای قبلی.
- عنوان و توضیحات متا، canonical، Open Graph، sitemap و robots.
- رندر HTML سمت سرور و خروجی ثابت عمومی شامل محتوای منتشرشده از ماژول‌های فعال.

متن ساده و بلوک‌ها به‌صورت escape‌شده نمایش داده می‌شوند؛ HTML ارسالی اجرا نمی‌شود. اگر بلوک اضافه کنید، نمایش صفحه از بلوک‌ها ساخته می‌شود؛ با حذف همه بلوک‌ها، متن ساده دوباره استفاده می‌شود. برای صفحه‌ی اصلی یک صفحه با آدرس `home` بسازید و منتشر کنید. سایر آدرس‌ها فعلاً انگلیسی هستند. لینک‌ها با اسلش پایانی یکسان‌سازی می‌شوند.

تصاویر به‌صورت پیش‌فرض در `media/` کنار دیتابیس نگهداری می‌شوند؛ مسیر مستقل با `CMS_MEDIA_DIR` قابل تعیین است. تصویر استفاده‌نشده یا مربوط به پیش‌نویس فقط با نشست معتبر دیده می‌شود. فقط تصاویر ارجاع‌شده از محتوای منتشرشده وارد خروجی ثابت می‌شوند.

## خروجی برای GitHub Pages

پنل و دیتابیس روی Pages اجرا نمی‌شوند. Pages تنها خروجی ثابت عمومی را میزبانی می‌کند؛ پنل و API نیازمند سرویس بک‌اند هستند.

بعد از ساخت و انتشار محتوا، سرور CMS را متوقف کنید؛ سپس در Bash/macOS/Linux:

```bash
CMS_PUBLIC_URL=https://YOUR-ACCOUNT.github.io/YOUR-REPOSITORY npm run export
```

در PowerShell ویندوز:

```powershell
$env:CMS_PUBLIC_URL = 'https://YOUR-ACCOUNT.github.io/YOUR-REPOSITORY'
npm run export
```

خروجی در `dist/` است. این پوشه شامل پنل، دیتابیس، اطلاعات کاربران و پیش‌نویس‌ها نیست. مسیر دارایی‌ها و canonical متناسب با زیرمسیر Pages ساخته می‌شود. فقط همین خروجی باید روی Pages منتشر شود. خروجی Pages قابلیت اختیاری است؛ برنامه فعلی، استقرار CMS روی هاست واقعی پس از تکمیل نسخه اول است. وب‌هوک و انتشار خودکار بعداً اضافه می‌شود. آرشیو دسته‌ها در خروجی ثابت ساخته می‌شود. ریدایرکت خروجی ثابت یک HTML انتقال با meta refresh است؛ ریدایرکت HTTP با وضعیت 308 فقط در سرور Node اجرا می‌شود. فرم تماس و لینک آن از خروجی ثابت حذف و این موضوع در خروجی دستور اعلام می‌شود؛ برای فرم به بک‌اند Node نیاز است. بعد از export سرور را دوباره اجرا کنید.

## مسیرهای پایه

| مسیر | کاربرد |
| --- | --- |
| `/admin` | پنل مدیر |
| `/api/auth/login`, `/api/auth/me`, `/api/auth/logout` | ورود و نشست |
| `/api/content` | فهرست و ساخت محتوا، نیازمند نشست |
| `/api/content/:id` | ویرایش یا حذف؛ نیازمند CSRF و نسخه‌ی فعلی |
| `/api/settings` | تنظیمات سایت؛ تغییر فقط توسط مدیر |
| `/api/modules` | تعریف ماژول‌ها |
| `/api/public/content` | محتوای منتشرشده، بدون ورود |
| `/api/users`, `/api/users/:id` | مدیریت حساب‌ها، فقط مدیر |
| `/api/auth/password` | تغییر رمز فعلی و خروج از همه نشست‌ها |
| `/api/auth/sessions`, `/api/auth/sessions/:id` | مشاهده و ابطال نشست‌های خود |
| `/api/media`, `/api/media/:id` | بارگذاری، alt و حذف تصویر |
| `/api/navigation` | منوی سایت؛ تغییر فقط مدیر |
| `/api/categories`, `/api/categories/:id` | دسته‌ها؛ خواندن برای نویسنده، تغییر فقط مدیر |
| `/articles/category/:slug/` | آرشیو مقالات منتشرشده دسته |
| `/api/redirects`, `/api/redirects/:id` | ساخت و حذف ریدایرکت، فقط مدیر |
| `/contact/` | فرم تماس، پس از فعال‌سازی توسط مدیر |
| `/api/public/contact-token`, `/api/public/contact` | دریافت توکن فرم و ارسال پیام بدون ورود |
| `/api/messages`, `/api/messages/:id` | صندوق تماس و وضعیت/حذف پیام، فقط مدیر |

برای نوشتن در API مدیریت، Origin باید با `CMS_ORIGIN` برابر باشد و هدر `X-CSRF-Token` از نشست فعلی گرفته شود. PUT و DELETE محتوا به `expected_updated_at` نیاز دارند. API عمومی در حال حاضر CORS بین دامنه‌ها ندارد؛ اتصال مستقیم یک frontend در دامنه‌ی دیگر باید جداگانه طراحی شود.

برای PUT کاربران، تصاویر و منو نیز `expected_updated_at` از نسخه فعلی لازم است. بارگذاری رسانه JSON نیست: `POST /api/media` با بایت‌های خام، `Content-Type: image/png` یا `image/jpeg` و هدر `X-Filename` شامل نام encodeURIComponent‌شده ارسال می‌شود. توکن CSRF همچنان لازم است. DELETE رسانه به `{expected_updated_at}` نیاز دارد. کاربران حذف نمی‌شوند؛ حساب غیرفعال می‌شود تا محتوای آن حفظ شود.

## دسته‌بندی، تماس و بکاپ

مدیر دسته‌ها را می‌سازد و نویسنده در ویرایش مقاله تا ۱۰ دسته انتخاب می‌کند. دسته بدون مقاله منتشرشده در ماژول فعال، آرشیو عمومی ندارد. حذف دسته استفاده‌شده رد می‌شود. آدرس‌های قدیمی به شناسه مقصد متصل‌اند و مستقیماً به آدرس فعلی می‌روند؛ حلقه انتقال ساخته نمی‌شود. آدرس رزروشده یک ریدایرکت را برای محتوای دیگر نمی‌توان استفاده کرد، مگر مدیر ابتدا ریدایرکت را حذف کند. صفحه اصلی همیشه مسیر `/` را نگه می‌دارد.

فرم تماس پیش‌فرض غیرفعال است؛ از «پیام‌های تماس» فعالش کنید. پیام در صندوق پنل ثبت می‌شود؛ اعلان یا پاسخ خودکار ایمیلی هنوز پیاده نشده است. `POST /api/public/contact` علاوه بر Origin صحیح، توکن دریافت‌شده از `/api/public/contact-token` می‌خواهد؛ نشست مدیر و CSRF مدیر لازم ندارد. توکن به IP اتصال متصل است، حداقل ۲ ثانیه پس از صدور و حداکثر ۲۰ دقیقه قابل استفاده است. فیلدهای `name`, `email`, `subject`, `message`, `website` ارسال شوند؛ `website` برای کاربر واقعی خالی است. حداکثر ۱۰ تلاش ارسال و ۳۰ صدور توکن در ۱۵ دقیقه برای هر IP؛ پشت پراکسی بدون پیکربندی IP واقعی، این محدودیت میان بازدیدکنندگان مشترک می‌شود. تنظیم پراکسی و محدودیت لبه قبل از استقرار لازم است.

صندوق حداکثر ۱۰هزار پیام نگه می‌دارد؛ مدیر باید پیام‌های غیرضروری را حذف کند. `GET /api/messages?page=1&status=new` هر بار حداکثر ۵۰ پیام برمی‌گرداند. وضعیت‌ها `new`, `read`, `archived` هستند. PUT/DELETE پیام، دسته و حذف ریدایرکت به `expected_updated_at` نیاز دارند. محتوای مقاله با آرایه `categoryIds` ذخیره می‌شود.

برای بکاپ، سرور را متوقف کنید:

```bash
npm run backup -- backups/site-2026-10-09
npm run backup -- --verify backups/site-2026-10-09
CMS_DB_PATH=recovered/cms.sqlite npm run restore -- backups/site-2026-10-09
```

بازیابی فقط در مسیر دیتابیس و پوشه رسانه تازه انجام می‌شود. اگر `CMS_MEDIA_DIR` در محیط تنظیم است، آن را هم به مسیر تازه تغییر دهید. پوشه بکاپ شامل داده خصوصی است و نباید روی وب یا گیت عمومی قرار بگیرد. [راهنمای کامل بکاپ و بازیابی](docs/BACKUP.fa.md) روش بررسی، تعویض مسیر نصب و مدیریت قفل داده را توضیح می‌دهد. سرور، create-admin، export از CLI و دستورهای بکاپ روی یک نصب همزمان اجرا نمی‌شوند؛ سرور را با توقف عادی ببندید تا قفل کنار دیتابیس آزاد شود.

## قبل از تحویل به مشتری

اعلان پیام تماس، تاریخچه نسخه/بازیابی ویرایش محتوا، بکاپ زمان‌بندی‌شده و بازیابی روی هاست واقعی، بررسی مرورگرها/صفحه‌خوان، ارزیابی مستقل امنیت و استقرار staging هنوز باقی است. `NODE_ENV=production` بدون HTTPS و کوکی Secure اجرا را رد می‌کند؛ این کنترل جای بررسی امنیت و راه‌اندازی صحیح پراکسی را نمی‌گیرد.

PNG/JPEG با decoder کامل خوانده و بدون metadata بازرمزگذاری می‌شود. برای ارتقای تصاویر نسخه قدیمی، سرویس را متوقف و پس از بکاپ `npm run normalize-media` را اجرا کنید. پیش از اجرای نسخه تازه از داده قبلی بکاپ بگیرید. migration تا schema 5 خودکار و افزایشی است، ولی downgrade خودکار پشتیبانی نمی‌شود و برای بازگشت بکاپ سازگار لازم است.

اطلاعات واقعی مشتری، کلیدها، رمزها و بکاپ‌ها وارد مخزن عمومی نمی‌شوند. برای هر مشتری دیتابیس و تنظیمات مستقل در نظر گرفته شده است. مجوز بازاستفاده از کد هنوز انتخاب نشده است؛ عمومی‌بودن مخزن به معنی وجود LICENSE نیست.

جزئیات در [نقشه راه](docs/ROADMAP.fa.md)، [معماری](docs/ARCHITECTURE.fa.md)، [استقرار](docs/DEPLOYMENT.fa.md) و [راهنمای مشارکت](CONTRIBUTING.md) است.

## امنیت نسخه 0.4

ورود دومرحله‌ای TOTP و کدهای بازیابی، بازیابی رمز از طریق SMTP، اعلان تغییر امنیتی، گزارش رخداد مدیر، پردازش کامل تصاویر و تنظیم IP پراکسی اضافه شده‌اند. فعال‌شدن MFA/SMTP نیازمند `CMS_SECURITY_KEY` خصوصی است؛ SMTP بدون تنظیم سرویس واقعی فعال نمی‌شود. [راهنمای امنیت و ارتقا](docs/SECURITY.fa.md) تنظیم کلید، سیاست مدیر، محدودیت‌ها و ارتقای تصاویر قدیمی را توضیح می‌دهد.

بکاپ داده کلید امنیتی را ذخیره نمی‌کند؛ کلید اصلی را جداگانه نگه دارید تا حساب‌های MFA پس از بازیابی قابل استفاده باشند. نسخه‌های جدید را ابتدا در staging و پس از بکاپ آزمایش کنید.

## قالب و طرح نسخه 0.5

دو قالب پایه شرکتی/خدماتی، رنگ و گوشه عناصر، چهار طرح صفحه، بخش‌های معرفی/کارت/پرسش و پیش‌نمایش خصوصی نسخه ذخیره‌شده فراهم‌اند. تغییر قالب داده محتوا را حفظ می‌کند. [راهنمای قالب‌ها](docs/TEMPLATES.fa.md) شیوه استفاده، محدودیت‌ها و افزودن طرح اختصاصی هر مشتری را توضیح می‌دهد.

آزمون جریان‌های اصلی مرورگر:

```bash
npx playwright install --with-deps chromium
npm run test:browser
```

این آزمون داده موقت و ارسال‌کننده ایمیل آزمایشی می‌سازد و در پایان پاک می‌کند؛ به حساب و SMTP واقعی متصل نمی‌شود. مسیر Chromium موجود با `CMS_TEST_BROWSER_EXECUTABLE` قابل تعیین است. تست API/خروجی با `npm test` مستقل اجرا می‌شود.
