# معماری نسخه اولیه

هسته‌ی مشترک با نصب و دیتابیس مستقل برای هر مشتری. ماژول‌ها در این نسخه تعریف نوع محتوا هستند، نه بسته‌های کد دلخواه یا سیستم افزونه‌ی کامل. کد مرورگری طراحی با مجوز مخصوص، در runtime جدا اجرا می‌شود؛ نصب افزونه یا کد سرور از پنل پشتیبانی نمی‌شود.

## اجزا

| مسیر | مسئولیت |
| --- | --- |
| `src/database.mjs`, `src/migrations.mjs` | اتصال SQLite و migration تراکنشی افزایشی |
| `src/auth.mjs` | هش رمز، نشست و کنترل تلاش ورود |
| `src/users.mjs` | مدیریت حساب‌ها و ابطال نشست‌ها |
| `src/media.mjs` | decode و بازرمزگذاری PNG/JPEG، ذخیره فایل و کنترل ارجاع |
| `src/blocks.mjs` | اعتبارسنجی بلوک‌ها و منو |
| `src/content.mjs` | اعتبارسنجی و ذخیره محتوا |
| `src/categories.mjs`, `src/redirects.mjs` | رابطه دسته/مقاله، آرشیو و تاریخچه مسیرها |
| `src/contact.mjs` | توکن فرم، محدودیت ارسال و صندوق پیام |
| `src/backup.mjs`, `src/data-lock.mjs` | بکاپ/بازیابی کامل و قفل نصب |
| `src/modules/registry.mjs` | تعریف مشترک صفحات و ماژول‌ها |
| `src/server.mjs` | API، کنترل دسترسی و نمایش سمت سرور |
| `src/render.mjs` | قالب نمونه عمومی، escaping و متادیتا |
| `public/admin.*` | پنل مستقل فارسی |
| `src/export.mjs` | ساخت خروجی عمومی ثابت |

ثبت قالب در `templates.mjs` و توسعه renderer/CSS یا ساخت frontend جدا از API، مسیر طراحی اختصاصی مشتری است. انیمیشن و طراحی سه‌بعدی از فضای طراحی نسخه 0.6 در قاب جدا اضافه می‌شود؛ اطلاعات محتوایی مستقل از صحنه سه‌بعدی می‌مانند. بلوک‌های عنوان، متن، تصویر و دکمه در نسخه 0.2 تعریف شده‌اند؛ نوع‌های جدید باید مدل و اعتبارسنجی مشخص داشته باشند.

## تصمیم‌ها

1. ابتدا سایت‌های شرکتی و خدماتی؛ فروشگاه، پرداخت و رزرو در دامنه‌ی نسخه اول نیستند.
2. Node.js 24 و SQLite برای اجرای نمونه محلی با حداقل وابستگی. runtime باید در عرضه تثبیت شود. SQLite تک‌نودی است؛ چند replica بدون ذخیره و هماهنگی مناسب نباید روی یک فایل کار کنند. Postgres در صورت نیاز به چند نمونه یا بار نوشتن بالاتر بررسی می‌شود.
3. پنل فقط به Origin مشخص‌شده درخواست نوشتن می‌پذیرد. فرانت عمومی می‌تواند HTML سمت سرور یا خروجی ثابت باشد. cross-origin API یک تصمیم جدا برای آینده است.
4. محتوای ساده به‌صورت escape‌شده نمایش داده می‌شود. ویرایشگر HTML خام اضافه نشده؛ rich-text باید همراه اعتبارسنجی و sanitization طراحی شود.
5. اطلاعات مشتری، نشست‌ها و رمزها در گیت ثبت نمی‌شوند. هر سایت کلیدها، دامنه، دیتابیس و بکاپ مستقل دارد.
6. migration شماره‌دار و تراکنشی از طرح‌های ۱ تا ۵ به ۶ وجود دارد و ارتقا و اجرای دوباره آن تست شده است. نسخه قدیمی نباید روی دیتابیس جدید اجرا شود. rollback خودکار وجود ندارد؛ بازگشت با بکاپ سازگار انجام می‌شود. ارتقای مشتری پس از بکاپ و آزمایش staging انجام می‌شود.

## خروجی ثابت

فرآیند: محتوای منتشرشده‌ی ماژول‌های فعال و تصاویر ارجاع‌شده → فایل‌های HTML، CSS و تصویر → انتشار عمومی. نشست‌ها، پنل، دیتابیس و تصاویر خصوصی وارد `dist` نمی‌شوند. هنگام استفاده از Pages، تغییرات محتوا تا اجرای دوباره export و انتشار ظاهر نمی‌شوند. فرم تماس و جست‌وجوی سمت سرور با خروجی ثابت به backend جدا نیاز دارند.

## محدودیت امنیت فعلی

امنیت حساب، MFA، reset SMTP، گزارش و پردازش کامل تصویر در نسخه 0.4 پیاده شده‌اند. `account-security.mjs` عامل دوم/بازیابی، `security-crypto.mjs` رمزگذاری/TOTP، `mail.mjs` صف و SMTP، `audit.mjs` گزارش و `proxy.mjs` زنجیره پراکسی را مدیریت می‌کنند. `image-processing.mjs` یک worker محدود را برای decoder کامل Sharp اجرا می‌کند. جداسازی worker، sandbox سیستم‌عامل نیست. جزئیات کلید مستقل، محدودیت‌ها و آزمون تحویل در SECURITY.fa.md است. این نسخه حسابرسی مستقل امنیتی ندارد.

## داده‌های نسخه 0.3

رابطه مقاله/دسته در جدول واسط ذخیره می‌شود. ریدایرکت به شناسه محتوا یا دسته متصل است؛ مقصد هر بار از محتوای منتشرشده و ماژول فعال حل می‌شود، پس آدرس خصوصی یا زنجیره ریدایرکت در خروجی عمومی نداریم. مسیرهای قدیمی با محتوای جدید برخورد نمی‌کنند؛ آدرس خود یک محتوا می‌تواند بازیابی شود. صفحه اصلی و مسیرهای سیستم تاریخچه انتقال ندارند.

پیام تماس داده خصوصی است و فقط مدیر آن را می‌خواند. توکن فرم و محدودیت‌ها در SQLite حفظ می‌شوند. IP خام ذخیره نمی‌شود؛ digest اتصال برای محدودیت/توکن به‌کار می‌رود. این کنترل‌ها جای سرویس مقابله با هرزنامه و محدودیت لبه در استقرار را نمی‌گیرند. فرم پیش‌فرض غیرفعال است تا صفحه قدیمی contact بدون تغییر باقی بماند.

بکاپ با توقف نویسنده، SQLite backup و کپی همه تصاویر ثبت‌شده گرفته می‌شود. قفل پوشه‌ای یک فرایند نویسنده را برای هر دیتابیس اعمال می‌کند. بازیابی در مسیر تازه پس از checksum، integrity_check و foreign_key_check انجام می‌شود. جزئیات عملیاتی در BACKUP.fa.md است.

## داده و نمایش نسخه 0.5

قالب سراسری در `site.theme` و طرح هر صفحه در ستون `content.template` نگه داشته می‌شوند. مدل بلوک‌ها مستقل از layout است. فقط کلیدهای ثبت‌شده و تنظیمات محدود پذیرفته می‌شوند؛ بلوک‌های معمولی کد اجرایی ندارند؛ فضای طراحی مجوز، داده و runtime جدا دارد. تصاویر و مقصدهای تو‌در‌تو در hero/cards در قواعد ارجاع/انتشار/export شرکت می‌کنند. preview از همان renderer با نشست و noindex/no-store استفاده می‌کند؛ قابلیت لینک اشتراکی ندارد. جزئیات در TEMPLATES.fa.md است.


## داده و اجرا نسخه 0.6

`designs` اشاره‌گر پیش‌نویس/نسخه عمومی و `design_revisions` snapshotهای مستقل HTML/CSS/JS/تصاویر را نگه می‌دارند. ذخیره پیش‌نویس اشاره‌گر عمومی را تغییر نمی‌دهد؛ انتشار با کنترل تعارض، رمز فعلی/MFA و بررسی نحوی انجام می‌شود. `users.design_access` دسترسی نویسنده به طراحی را تعیین می‌کند و مدیر انتشار را کنترل می‌کند. `design_previews` قابلیت خواندن موقت را به نشست و نسخه محدود می‌کند؛ کلید آن فقط هش و در بکاپ حذف می‌شود.

`designs.mjs` داده/مجوز/انتشار، `design-api.mjs` API و `design-runtime.mjs` سند و CSP runtime را می‌سازند. `design-presets.mjs` نمونه سه‌بعدی و `public/designer.js` ویرایشگر/پیش‌نمایش/تاریخچه را فراهم می‌کنند. بلوک code-design شناسه طرح را نگه می‌دارد و نسخه منتشرشده همان طرح را حل می‌کند. عنوان/متن جایگزین در HTML اصلی است. تصویر طرح در قواعد visibility، حذف و export شرکت می‌کند.

runtime با iframe و CSP sandbox بدون allow-same-origin اجرا می‌شود. CORS فقط فایل‌های runtime/vendor را برای origin جداشده مجاز می‌کند؛ API همچنان بسته است. Three از دو فایل build محلیِ allowlist‌شده سرو می‌شود. Node برای کد کاربر فقط subprocess نحوی محدود اجرا می‌کند و آن را eval نمی‌کند. خروجی ثابت نسخه‌های عمومی را همراه LICENSE و تنظیمات میزبان قابل اعمال کپی می‌کند؛ origin جدا از سرویس احراز هویت لازم است. شرح مرزها و میزبانی در DESIGN-WORKSPACE.fa.md است.
