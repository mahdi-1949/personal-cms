# معماری نسخه اولیه

هسته‌ی مشترک با نصب و دیتابیس مستقل برای هر مشتری. ماژول‌ها در این نسخه تعریف نوع محتوا هستند، نه بسته‌های کد دلخواه یا سیستم افزونه‌ی کامل. اجرای کد مشتری یا نصب افزونه‌ی ناشناخته پیش‌بینی نشده است.

## اجزا

| مسیر | مسئولیت |
| --- | --- |
| `src/database.mjs` | اتصال SQLite و طرح اولیه دیتابیس |
| `src/auth.mjs` | هش رمز، نشست و کنترل تلاش ورود |
| `src/content.mjs` | اعتبارسنجی و ذخیره محتوا |
| `src/modules/registry.mjs` | تعریف مشترک صفحات و ماژول‌ها |
| `src/server.mjs` | API، کنترل دسترسی و نمایش سمت سرور |
| `src/render.mjs` | قالب نمونه عمومی، escaping و متادیتا |
| `public/admin.*` | پنل مستقل فارسی |
| `src/export.mjs` | ساخت خروجی عمومی ثابت |

جایگزین‌کردن قالب `render.mjs` یا ساخت frontend جدا از API، مسیر طراحی اختصاصی مشتری است. انیمیشن و طراحی سه‌بعدی بعداً در frontend همان مشتری اضافه می‌شود؛ اطلاعات محتوایی باید مستقل از صحنه سه‌بعدی بمانند. مدل بلوک‌های محتوا در مرحله بعد اضافه می‌شود تا مشتری بتواند بخش‌های مجاز طراحی را تغییر دهد.

## تصمیم‌ها

1. ابتدا سایت‌های شرکتی و خدماتی؛ فروشگاه، پرداخت و رزرو در دامنه‌ی نسخه اول نیستند.
2. Node.js 24 و SQLite برای اجرای نمونه محلی با حداقل وابستگی. runtime باید در عرضه تثبیت شود. SQLite تک‌نودی است؛ چند replica بدون ذخیره و هماهنگی مناسب نباید روی یک فایل کار کنند. Postgres در صورت نیاز به چند نمونه یا بار نوشتن بالاتر بررسی می‌شود.
3. پنل فقط به Origin مشخص‌شده درخواست نوشتن می‌پذیرد. فرانت عمومی می‌تواند HTML سمت سرور یا خروجی ثابت باشد. cross-origin API یک تصمیم جدا برای آینده است.
4. محتوای ساده به‌صورت escape‌شده نمایش داده می‌شود. ویرایشگر HTML خام اضافه نشده؛ rich-text باید همراه اعتبارسنجی و sanitization طراحی شود.
5. اطلاعات مشتری، نشست‌ها و رمزها در گیت ثبت نمی‌شوند. هر سایت کلیدها، دامنه، دیتابیس و بکاپ مستقل دارد.
6. دیتابیس شماره طرح اولیه دارد؛ مهاجرت افزایشی نسخه‌های بعد، ابزار rollback و آزمون upgrade هنوز ساخته نشده است. ارتقای مشتری باید پس از بکاپ و آزمایش staging انجام شود.

## خروجی ثابت

فرآیند: محتوای منتشرشده‌ی ماژول‌های فعال → فایل‌های HTML و CSS → انتشار عمومی. نشست‌ها، پنل و دیتابیس وارد `dist` نمی‌شوند. هنگام استفاده از Pages، تغییرات محتوا تا اجرای دوباره export و انتشار ظاهر نمی‌شوند. فرم تماس و جست‌وجوی سمت سرور با خروجی ثابت به backend جدا نیاز دارند.

## محدودیت امنیت فعلی

کنترل‌های امنیتی اولیه پیاده شده‌اند؛ این نسخه حسابرسی مستقل امنیتی ندارد. نرخ ورود در دیتابیس حفظ می‌شود، اما سرور reverse-proxy را خودکار اعتماد نمی‌کند؛ تنظیم درست IP واقعی، rate limit لبه، timeout، اندازه درخواست و TLS برای استقرار لازم است. MFA، ثبت رخداد امنیتی، بازیابی رمز و مدیریت/ابطال نشست‌ها در نقشه راه هستند.
