# بکاپ و بازیابی

از نسخه 0.3 دستورهای بکاپ کامل، بررسی و بازیابی فراهم‌اند. این روش آفلاین است: سرویس CMS را پیش از بکاپ متوقف کنید. دیتابیس، تصاویر و فایل تنظیمات محیطی هر نصب باید مسیر مستقل داشته باشند.

## تهیه بکاپ

پس از توقف سرویس، با همان `CMS_DB_PATH` و `CMS_MEDIA_DIR` نصب اصلی:

```bash
npm run backup -- backups/site-2026-10-09
npm run backup -- --verify backups/site-2026-10-09
```

مسیر خروجی باید تازه باشد. پوشه موجود جایگزین نمی‌شود. اگر متغیرهای محیطی تنظیم نشده باشند، دیتابیس `data/cms.sqlite` و رسانه `data/media` استفاده می‌شوند. بعد از اتمام موفق بکاپ، سرویس اصلی را دوباره اجرا کنید.

پوشه خروجی شامل `cms.sqlite`، پوشه `media` و `manifest.json` است. نسخه SQLite با API بکاپ داخلی Node گرفته می‌شود؛ همه تصاویر ثبت‌شده، از جمله تصاویر خصوصی، کپی می‌شوند. فایل‌های رهاشده که در جدول رسانه ثبت نشده‌اند کپی نمی‌شوند. نشست‌ها و توکن‌های موقت در نسخه پشتیبان پاک می‌شوند؛ نشست نصب اصلی تغییر نمی‌کند.

SHA-256 و اندازه هر فایل، سلامت SQLite، کلیدهای خارجی و مطابقت رسانه با دیتابیس بررسی می‌شوند. تصویر گم‌شده یا خراب‌شدن فایل، عملیات را ناموفق می‌کند. بکاپ رمزگذاری‌شده یا امضاشده نیست؛ checksum خرابی فایل را تشخیص می‌دهد و اصالت یک بکاپ دریافتی از شخص دیگر را تضمین نمی‌کند. فقط از بکاپ مورداعتماد خودتان بازیابی کنید.

پوشه بکاپ شامل هش رمزها و پیام‌های تماس است. خارج از مسیر عمومی وب، با دسترسی محدود نگهداری شود. `backups/` در gitignore است؛ نام‌های دیگر را نیز وارد مخزن عمومی نکنید. کد CMS و متغیرهای محیطی/کلیدها جزو بکاپ داده نیستند؛ نسخه کد و تنظیمات را جداگانه در محل خصوصی ثبت کنید. دسترسی فایل‌ها در محیط POSIX محدود می‌شود؛ در ویندوز ACL مناسب را تنظیم کنید.

## بازیابی

همیشه در مسیر تازه بازیابی کنید. این دستور دیتابیس یا پوشه رسانه موجود را بازنویسی نمی‌کند:

```bash
CMS_DB_PATH=recovered/cms.sqlite npm run restore -- backups/site-2026-10-09
```

اگر رسانه اصلی سفارشی است، مسیر تازه آن را صریحاً تعیین کنید:

```bash
CMS_DB_PATH=recovered/cms.sqlite CMS_MEDIA_DIR=recovered/images npm run restore -- backups/site-2026-10-09
```

در PowerShell متغیرها را پیش از دستور تنظیم کنید:

```powershell
$env:CMS_DB_PATH = 'recovered/cms.sqlite'
$env:CMS_MEDIA_DIR = 'recovered/images'
npm run restore -- backups/site-2026-10-09
```

بازیابی ابتدا در مسیرهای موقت انجام و بررسی می‌شود. دیتابیس نسخه قدیمی به schema جاری ارتقا پیدا می‌کند؛ schema جدیدتر از برنامه رد می‌شود. تمام نشست‌ها باطل می‌شوند و کاربران دوباره وارد می‌شوند.

سایت بازیابی‌شده را با همان متغیرهای مسیر، روی پورت جداگانه محلی اجرا کنید. ورود، صفحات، تصاویر، پیام‌ها و داده واقعی پروژه را بررسی کنید. بعد از موفقیت بررسی، سرویس قبلی را متوقف و پیکربندی سرویس را به مسیر تازه تغییر دهید. نصب قبلی را تا اطمینان از بازیابی نگه دارید. برای برگشت به کد قدیمی، بکاپ و نسخه کد سازگار لازم است؛ downgrade خودکار وجود ندارد.

## قفل داده و محدودیت‌ها

سرور، ساخت مدیر، export از CLI، بکاپ و بازیابی از یک قفل پوشه‌ای کنار دیتابیس استفاده می‌کنند. یک نصب، یک سرور نویسنده دارد. اجرای همزمان این دستورها رد می‌شود؛ سرور را با SIGTERM/SIGINT ببندید تا قفل آزاد شود. در صورت crash یا قطع برق، قفل ممکن است باقی بماند: پیش از حذف دستی پوشه `cms.sqlite.cms-lock`، مطمئن شوید هیچ فرایند CMS به آن دیتابیس دسترسی ندارد. ابزارهای بیرونی یا نسخه‌های قدیمی CMS باید جداگانه متوقف شوند؛ قفل جای محدودیت دسترسی سیستم‌عامل را نمی‌گیرد. پوشه رسانه را میان نصب‌ها مشترک نکنید.

در خطای معمول، فایل‌های موقت پاک می‌شوند. قطع برق هنگام انتقال فایل‌ها می‌تواند مسیر موقت یا بخشی از نصب تازه را باقی بگذارد؛ نصب اصلی دست‌نخورده می‌ماند. مسیر تازه را بررسی و سپس بازیابی را دوباره انجام دهید. بکاپ زمان‌بندی‌شده، رمزگذاری، انتقال خارج از سرور و آزمون بازیابی روی هاست واقعی هنوز باید در مرحله استقرار تنظیم شوند. آزمون بازیابی این نسخه روی داده آزمایشی انجام شده است.
