# فضای کار طراح — نسخه 0.7

طراح می‌تواند از پنل طرح اختصاصی مرورگری بسازد، HTML/CSS/JavaScript را ویرایش کند، پیش‌نویس را خودکار ذخیره کند و در اندازه دسکتاپ، تبلت و موبایل ببیند. کد هر طرح در دیتابیس همان مشتری نگه داشته می‌شود؛ هسته CMS در گیت‌هاب توسعه می‌یابد. برای انتقال طراحی مشتری به مخزن مستقل او باید فرآیند نسخه‌بندی پروژه جداگانه تعریف شود؛ ذخیره در پنل، commit خودکار در گیت‌هاب نیست.

## جریان کار

1. مدیر در «کاربران» برای حساب نویسنده، «دسترسی طراحی با کد» را فعال می‌کند. نشست‌های قبلی آن حساب با تغییر دسترسی بسته می‌شوند. مدیر همیشه دسترسی طراحی دارد.
2. در «فضای کار طراح»، طرح خالی، «معرفی سه‌بعدی» یا «نمایش مدل GLB» را بسازید. نام، HTML، CSS و JavaScript قابل تغییرند. JavaScript به‌صورت ES module در مرورگر اجرا می‌شود. رویدادها در فایل JavaScript نوشته شوند؛ script و handler در HTML به‌صورت عمومی مجاز نیستند.
3. تغییرات پس از مکث ۱٫۴ ثانیه ذخیره می‌شوند. «ذخیره و پیش‌نمایش» آخرین ذخیره را اجرا می‌کند. کنسول، خطا/هشدار/پیام همان قاب را به‌صورت متن نشان می‌دهد. در تعارض ویرایش، ذخیره متوقف و کد موجود در ویرایشگر حفظ می‌شود؛ کد را کپی و نسخه تازه را باز کنید.
4. پیش‌نمایش یک لینک موقت دارای قابلیت خواندن است؛ حداکثر ۱۰ دقیقه و تا معتبرماندن نشست ایجادکننده قابل استفاده است. هر کس لینک کامل را داشته باشد در این مدت می‌تواند آن نسخه را ببیند. لینک را برای انتشار عمومی یا اشتراک دائمی استفاده نکنید. توکن در دیتابیس فقط هش می‌شود و خروج، انقضا یا لغو نشست/مجوز، دسترسی را می‌بندد.
5. نسخه‌های قبلی را از تاریخچه پیش‌نمایش یا به پیش‌نویس بازیابی کنید. ۴۰ نسخه اخیر و نسخه عمومیِ قدیمی‌تر حفظ می‌شوند. بازیابی نسخه متفاوت، نسخه تازه می‌سازد و نسخه عمومی را تغییر نمی‌دهد.
6. مدیر با رمز فعلی و عامل دوم در صورت فعال‌بودن، پیش‌نویس یا نسخه منتخب تاریخچه را منتشر می‌کند. «لغو انتشار» نمای کد را از سایت حذف می‌کند و متن جایگزین باقی می‌ماند. انتشار، لغو انتشار و بازیابی در گزارش رخداد ثبت می‌شوند. خطای نحوی JavaScript انتشار را رد می‌کند؛ این بررسی اجرای کد یا تضمین درستی رفتار آن نیست.
7. در ویرایش صفحه، بلوک «طرح با کد / سه‌بعدی» را اضافه کنید؛ طرح، عنوان، متن جایگزین و ارتفاع ۲۰۰ تا ۱۲۰۰ پیکسل را تعیین کنید. برای صفحه اصلی آدرس `home` را انتخاب کنید. صفحه را نخست به‌صورت پیش‌نویس ذخیره، با پیش‌نمایش موبایل/دسکتاپ بررسی و سپس منتشر کنید.

تغییر نسخه عمومی یک طرح بر همه صفحاتی که به همان طرح متصل‌اند اثر می‌گذارد؛ نام صفحات در ویرایشگر نمایش داده می‌شود. نسخه عمومی کد فقط وقتی URL عمومی دارد که یک محتوای منتشرشده در ماژول فعال به آن ارجاع دهد. کد پیش‌نویس از مسیر عمومی قابل دریافت نیست. پیش‌نمایش خصوصی صفحه، نسخه منتشرشده طرح متصل را با قابلیت موقت مستقل نمایش می‌دهد و کد پیش‌نویس طراح را به نویسنده عادی نمی‌دهد.

## کد و دارایی‌ها

Three.js نسخه ثابت `0.186.1` از وابستگی محلی نصب‌شده سرو می‌شود؛ CDN لازم نیست:

```js
import * as THREE from 'three';
```

در «دارایی‌های مجاز طرح»، حداکثر بیست تصویر، مدل GLB یا فونت WOFF ثبت‌شده را انتخاب کنید. شناسه تصویر در همان فرم نشان داده می‌شود. مثال:

```js
const image = document.createElement('img');
image.src = cms.assets['MEDIA_ID'];
image.alt = 'توضیح تصویر';
document.querySelector('.custom-section').append(image);
```

مسیر تصویر به همان نسخه و پیش‌نمایش محدود است. تصویر داخل نسخه‌های حفظ‌شده طراحی قابل حذف نیست. تصاویر طرحِ ارجاع‌شده از صفحه منتشرشده، مانند تصاویر سایر بلوک‌ها عمومی می‌شوند. لینک خصوصی `/media/…` را مستقیماً در کد قرار ندهید؛ `cms.assets` برای تصویر انتخاب‌شده مسیر درست تولید می‌کند. بارگیری با TextureLoader و تصویر به URL مجاز محدود است؛ fetch/XHR فقط به assets همان نسخه و blob محلی مجاز است؛ API مدیریت و منابع خارجی بسته‌اند.

نمونه سه‌بعدی شامل هندسه، دوربین و نور واقعی است. تراکم پیکسل حداکثر ۱٫۵، توقف حرکت توسط کاربر، احترام به کاهش حرکت سیستم، توقف حلقه در صفحه پنهان/صحنه خارج دید، resize و آزادسازی منابع دارد. نبود WebGL به پیام جایگزین منتهی می‌شود. عنوان و توضیح بخش در HTML اصلی صفحه می‌مانند؛ محتوای مهم تجاری را فقط داخل canvas یا قاب قرار ندهید. عملکرد و خوانایی صحنه واقعی مشتری باید جداگانه سنجیده شود.

## مدل GLB و فونت برند

1. از «دارایی‌های طراحی» در فضای طراح، GLB یا WOFF بارگذاری کنید. GLB تا ۲۰ MiB و WOFF تا ۲ MiB؛ فایل را تا انتشار، منابع همان پروژه نگه می‌دارند. لوگو و آیکون تصویری PNG/JPEG از بخش تصاویر قابل استفاده‌اند؛ SVG هنوز پشتیبانی نمی‌شود.
2. در نمونه «نمایش مدل GLB»، تازه‌ترین مدل به‌طور خودکار انتخاب می‌شود. در «دارایی‌های مجاز طرح» می‌توانید مدل را عوض کنید؛ نمونه نخستین مدل انتخاب‌شده را نمایش می‌دهد. انتخاب را ذخیره و پیش‌نمایش را تازه کنید.
3. در همان بخش، «استفاده از فونت» فایل را انتخاب و کد FontFace به JavaScript اضافه می‌کند. فونت فقط در قاب طرح اعمال می‌شود. خانواده قلم CSS قالب صفحه اصلی، سربرگ و دیگر بخش‌ها مستقل است.
4. انتشار مدیر و بلوک «طرح با کد» مانند سایر طرح‌ها عمل می‌کنند. مدل/فونت نسخه پیش‌نویس یا تاریخچه، تنها با انتشارِ نسخه ارجاع‌شده عمومی می‌شود؛ دارایی‌های تاریخچه قابل حذف نیستند.

مدل باید glTF 2.0 معتبر، uncompressed و دارای تمام buffer/texture در BIN داخلی باشد. هر URI حتی data URI رد می‌شود. Draco، Meshopt، KTX2 و extensionهای دیگر به‌جز KHR_materials_unlit و KHR_texture_transform فعلاً پشتیبانی نمی‌شوند. تعداد nodes تا ۲۰۰۰، meshes تا ۱۰۰۰، تصاویر تا ۲۰ ، مجموع accessor count تا چهار میلیون و workload حاصل از تکرار mesh در nodeها تا دو میلیون vertex/index محدود است. این سقف‌ها تضمین سرعت مدل روی تلفن واقعی نیستند. خروجی GLB استاندارد دارای texture داخلی از ابزار طراحی لازم است.

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
const modelId = Object.keys(cms.assetInfo).find(id => cms.assetInfo[id].mime === 'model/gltf-binary');
if (modelId) {
  const model = await new GLTFLoader().loadAsync(cms.assets[modelId]);
  scene.add(model.scene);
}
```

`cms.assetInfo` فقط نام، MIME و حجم دارایی‌های انتخاب‌شده را دارد. GLTFLoader و BufferGeometryUtils/SkeletonUtils از نسخه ثابت Three محلی سرو می‌شوند. سایر addonها مسیر عمومی ندارند. نمونه مدل از AnimationMixer استفاده می‌کند؛ پیش‌نمایش مدل بدون GLB یا WebGL پیام جایگزین دارد.

WOFF2 و TTF/OTF مستقیم پذیرفته نمی‌شوند؛ فونت دارای حق استفاده را به WOFF تبدیل کنید. WOFF دارای metadata/private block پذیرفته نمی‌شود؛ fonttools یا ابزار خروجی فونت باید این بخش‌ها را حذف کند. فونت سیستم را برای خطای decode و نویسه‌های موجودنبودن حفظ کنید. فونت نمونه تست، زیرمجموعه مجاز DejaVu Sans است و برای طراحی مشتری نصب نمی‌شود.

## مرز اجرا

کد HTML/CSS/JavaScript در iframe با `sandbox="allow-scripts"` و بدون `allow-same-origin` اجرا می‌شود. پاسخ HTML سرور نیز CSP sandbox دارد تا بازکردن مستقیم URL، این جداسازی را حذف نکند. کد به DOM پنل، کوکی، localStorage و API مدیریت دسترسی ندارد. CSP اجرای script را به entry/bridge همان نسخه، importmap ثابت و کتابخانه Three محلی محدود می‌کند. fetch/XHR فقط به assets همان نسخه و blob بافت دسترسی دارد؛ API، origin خارجی، فرم، frame فرزند، worker، رسانه خارجی و object بسته‌اند. ناوبری در خود قاب ممکن است، ولی بازکردن popup و تغییر صفحه والد مجاز نیست؛ کد را پیش از انتشار بازبینی کنید و فقط تصاویر مورد نیاز را به طرح بدهید. CSS inline فقط داخل قاب مجاز است؛ سیاست پنل تغییری نمی‌کند.

CORS باز فقط برای فایل‌های runtime و کتابخانه تأییدشده است؛ API مدیریت CORS باز ندارد. پیام‌های کنسول فقط از `contentWindow` قاب جاری پذیرفته و با `textContent` و سقف تعداد/طول نمایش داده می‌شوند. رمز، CSRF، شناسه نشست و داده خصوصی پنل به قاب ارسال نمی‌شود. طرح منتشرشده شامل JavaScript مرورگری عمومی است؛ کلید خصوصی یا رمز را در کد آن نگذارید.

کد روی سرور eval/import نمی‌شود. Node فقط هنگام انتشار با subprocess محدود و `--check --input-type=module` نحو JavaScript را می‌خواند؛ زمان و همزمانی محدود است. PHP، Node.js، نصب بسته دلخواه، React/TSX و addonهای خارج از فهرست تأییدشده در پنل این نسخه پشتیبانی نمی‌شوند. سقف هر طرح: HTML و CSS هرکدام ۶۴ KiB، JavaScript برابر ۱۲۸ KiB، حداکثر ۵۰ پروژه و مجموع ۶۴ MiB متن نسخه‌ها. فایل‌ها و قابلیت‌های دیگر به مدل، مجوز و مسیر build مشخص نیاز دارند.

## سیستم طراحی و کتابخانه

رنگ برند و گوشه عناصر، خانواده قلم سیستم/Tahoma/serif، فاصله بخش‌ها، اندازه متن و سربرگ کنارهم/وسط‌چین از «قالب و ظاهر سایت» تنظیم می‌شوند. فونت WOFF برای طرح کد قابل بارگذاری است؛ تنظیم فونت سفارشی سراسری قالب و WOFF2 هنوز باقی است. رنگ‌ها hex و دیگر گزینه‌ها enum محدودند.

کتابخانه بخش‌ها: معرفی، خدمات، مراحل همکاری، نمونه‌کار، نظر مشتری، آمار و پرسش‌های متداول. طرح کامل صفحه: اصلی، درباره، فهرست خدمات، جزئیات خدمت، پروژه، مقاله و اطلاعات تماس. این‌ها بلوک‌های قابل ویرایش‌اند؛ متن نمونه، داده واقعی کسب‌وکار یا تأییدیه مشتری محسوب نمی‌شود. فرم تماس پویا همچنان از بخش پیام‌های تماس فعال می‌شود و صفحه `/contact/` دارد.

طرح صفحه بلوک‌ها را جایگزین می‌کند و برای محتوای موجود تأیید داخل پنل می‌گیرد؛ افزودن بخش به انتها اضافه می‌کند. دکمه برگشت، آخرین تغییر طرح/افزودن بخش/کشیدن ترتیب را برمی‌گرداند. نام و آدرس صفحه با اعمال preset تغییر نمی‌کنند. فهرست فشرده عنوان‌ها و عنوان خود بلوک‌ها قابل کشیدن‌اند؛ دکمه‌های بالا/پایین برای صفحه‌کلید و موبایل باقی‌اند. پیش‌نمایش صفحه، ذخیره‌شده‌ها را نمایش می‌دهد؛ صفحه محتوا هنوز autosave یا تاریخچه نسخه ندارد.

## بکاپ، export و میزبانی

migration افزایشی schema 6 با حفظ داده قدیمی اجرا می‌شود. قبل از ارتقا بکاپ بگیرید. بکاپ پروژه‌های طراحی، نسخه‌ها، نسخه منتشرشده، دسترسی‌ها و تصاویر را حفظ می‌کند؛ نشست‌ها و توکن پیش‌نمایش حذف می‌شوند. برای بازیابی MFA، کلید امنیتی اصلی همچنان جداگانه لازم است.

export فقط نسخه منتشرشده طرح‌های ارجاع‌شده در صفحات عمومی و تصاویر مجاز آن نسخه را کپی می‌کند. پوشه `design-vendor` شامل کتابخانه و LICENSE.txt آن است. پیش‌نویس، تاریخچه خصوصی، preview و اطلاعات حساب صادر نمی‌شوند. مسیرها بر اساس `CMS_PUBLIC_URL` و زیرمسیر تنظیم می‌شوند.

**خروجی دارای کد را روی origin جدا از پنل یا هر سرویس دارای نشست خصوصی میزبانی کنید.** فایل `_headers` برای میزبان‌هایی که این قالب را می‌پذیرند ساخته می‌شود؛ در میزبان دیگر معادل آن را تنظیم کنید:

- `Access-Control-Allow-Origin: *` برای فایل‌های JavaScript runtime و design-vendor؛ برای تصاویر طرحِ استفاده‌شده در texture نیز لازم است.
- `Content-Security-Policy: sandbox allow-scripts; frame-ancestors https://PUBLIC-ORIGIN` برای HTML runtime.
- `Referrer-Policy: no-referrer` و `X-Content-Type-Options: nosniff` برای runtime.

قاب در خروجی ثابت نیز sandbox دارد، ولی policy HTTP برای بازکردن مستقیم HTML runtime باید توسط میزبان اعمال شود؛ meta نمی‌تواند CSP sandbox را اعمال کند. GitHub Pages هدر دلخواه `_headers` را اعمال نمی‌کند، بنابراین برای طرح کدنویسی‌شده میزبانی Node یا میزبان قابل تنظیم پیشنهاد می‌شود. خروجی معمولی بدون طرح کد همچنان مانند قبل قابل استفاده است. export این نیاز را به‌صورت warning گزارش می‌کند؛ فرآیند export به‌تنهایی تنظیمات میزبان را تأیید نمی‌کند.

## ادامه توسعه

مدل‌های فشرده و loaderهای دیگر؛ WOFF2، فونت سراسری قالب و SVG ایمن؛ محیط build برای کامپوننت‌های React/TSX؛ بازبینی طراح و مدیر با گردش تأیید؛ تاریخچه/کپی/autosave صفحات؛ سنجش عملکرد روی موبایل واقعی، صفحه‌خوان و مرورگرهای دیگر؛ و راه‌اندازی staging، SMTP، بکاپ زمان‌بندی‌شده و بازیابی روی هاست واقعی باقی‌اند. هیچ‌یک در این نسخه تکمیل‌شده فرض نمی‌شود.
